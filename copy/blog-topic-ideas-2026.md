# LIP Services — Blog Topic Ideas (pain-first, long-tail)
**Date:** 2026-08-20
**Purpose:** Feed Phase 1 step 5 of `plan-of-attack-2026.md` ("Repurpose existing trade video scripts into blog posts") — a topic queue so future posts aren't decided ad hoc. Companion to `pages/seo-meta-schema-index.md`, which is still the source of truth for keywords actually in use — check there before drafting, this list is proposals, not claims.

**Framing rule (Robert, 2026-08-20):** write to the fix/pain, not the solution. Title and keyword should match what a tradie is actually feeling or typing ("why do my quotes go cold") not what we're selling ("quote follow-up automation"). The solution still gets the internal link — it just isn't the headline.

**Scope:** trades vertical only, matching the 2026-08-17 decision to go deep before wide (36-combo matrix stays in the Parking Lot until other verticals have sourced pain points).

**Sequencing decision (2026-08-20):** these get filmed first, not written first. `LIP-Command-Centre/Video Script/video-topic-queue-2026.md` has the same 10 topics as Brief-ready video rows — the plan is Command Centre generates and renders the video for a topic, it goes live, then this file's post repurposes that footage/script into the blog piece. Matches the cheapest-content-first principle already used for the 4 trades landing pages. Don't draft a blog post from this list before its matching video exists, unless there's a good reason to skip ahead for a specific topic.

## Sourcing rule (Robert, 2026-08-20)
Any claim/stat in a post needs a real, citable source — not marketing spin. Command Centre's Blog tab (Research module) now has a **"Source to cite"** field alongside Topic: paste a real stat + its source there and Claude will use that exact figure and name the source inline; leave it blank and Claude won't invent one at all. Find the source *before* running the post through the generator, not after.

## Suggested release order
Sequenced so the posts needing no extra research go first, and the two needing a sourced stat get flagged up front so you can go find the source before you sit down to generate rather than mid-flow. One a week is a reasonable pace against everything else in motion — adjust freely, this is a queue not a deadline.
